# ナビトラ ― GPS・カーナビ・アマチュア無線が出会った時代

**ナビトラ（NAVITRA）**は、GPS受信機で測定した位置をアマチュア無線のパケット通信で送り、仲間の位置やメッセージを地図上で表示するために生まれた**日本発の位置情報通信システム**です。名称は「ナビゲーション」と「トランシーバー」を組み合わせたもので、ケンウッドが商標として使用しました。

今ではスマートフォンで位置を共有できますが、1990年代には、**衛星測位も電子地図も通信手段も別々の装置**でした。GPS受信機と無線機をケーブルでつなぎ、カーナビやWindowsパソコンのCD-ROM地図へ仲間の現在位置を描く。それを携帯電話のようなデータ通信が気軽に使えなかった時代に、アマチュア無線家が自分で実現したのがナビトラであり、個人だけでなく、複数の企業がそれを付加価値として搭載した製品を販売するまでに至りました。

| 項目 | 内容 |
| --- | --- |
| 主な時代 | 1990年代後半～2000年代を中心に日本で利用 |
| 伝送方式 | [AX.25パケット通信](AX25パケット.md)の情報部分に、`$PNTS`で始まるナビトラ独自形式のデータを載せる |
| 扱う情報 | 位置、移動方向、速度、アイコン、短い文字メッセージ |
| 主な構成 | GPS受信機、TNCまたはTNC内蔵FM無線機、表示用のPC地図／カーナビ |
| 類似システム | 米国発の[APRS](APRS.md)。共通のAX.25を使うが、**情報形式はそのままでは互換ではない** |
| 今日の位置づけ | 歴史的な日本独自システム。対応旧機種による再現や解析・自作実験が中心 |

## 概要 ― 「リモコン亭主システム」から生まれた

ナビトラのルーツは、パソコンとアマチュア無線の研究グループ**NAZCA**がNIFTY-ServeのFGPS（GPSに関するフォーラム）で発表した、**「リモコン亭主システム」**にあります。

これは単に奇抜な名前だったというだけではありません。GPS受信機で得た位置データを無線で送る形式や、受信した移動局の位置を地図に表示する方法などが、後のナビトラへ引き継がれました。やがてケンウッドがTNC内蔵無線機やカーナビ連携を製品化します。**アマチュアのアイデアが、市販の電子機器に取り込まれていった歴史**を示す好例です。

この系譜は、CQ出版社『新世界の扉を開こう デジタル&インターネット通信』第5章の公開試読で、**NAZCA・FGPS・リモコン亭主システムの名称まで**確認できます。[CQ出版社：ナビトラの世界に触れてみよう（PDF）](https://www.cqpub.co.jp/hanbai/books/14/14951/14951_p145.pdf)。

ナビトラで通信するためには、位置を取得する装置と電波を送る装置が必要です。自局が移動しないのであれば、位置は固定値でもかまいません。表示には専用ナビ機器のほか、パソコンの地図ソフトや独自プログラムも使われました。車載パソコンとGPSが現在ほど小さく安価ではなかった時代、これらを取り付けて動かすこと自体が電子工作でした。

## 成り立ちから現在まで

| **1998年12月** | 国内向けケンウッド**TH-D7**を発売。ナビトラ機能とTNCを内蔵したハンディ機が登場 |

| **2007年** | 国内向け**TM-D710**シリーズがナビトラとAPRSの両方に対応し、日本・海外で異なっていた運用方式の橋渡しとなる |
| **2010年代以降** | インターネット地図、スマートフォン、APRSの普及が進み、ナビトラ単独の新規システム構築は難しくなっていく |

1998年7月10日の『INTERNET Watch』には、プロアトラス98とケンウッドによる連携の仕組みが詳しく記録されています。ナビトラ基地局が受信したパケットをネット経由でアルプス社のサーバーへ送り、無線局の呼出符号・位置・メッセージをプロアトラス98側へ表示するものでした。**無線免許のない人も、インターネット経由で地図を閲覧できる**と説明されています。

[『INTERNET Watch』1998年7月10日「アルプスがインターネットでナビトラ情報が得られる電子地図ソフトを発売」](https://internet.watch.impress.co.jp/www/article/980710/alps.htm)。

これは無線とインターネットが結びつく、現在のAPRS-ISと同じ方向の発想です。ただし**ナビトラとAPRS-ISは別のシステム**であり、1998年のアルプス社のサービスが現在も提供されているという意味ではありません。

## あの頃の電子地図とGPS

### アルプス社「プロアトラス」

**プロアトラス97／98／2000**は、株式会社アルプス社が提供していたパソコン向け電子地図ソフトです。当時は現在のように地図画像がネットから随時届くわけではなく、**CD-ROMやDVD-ROMから地域ごとの地図を読み出して表示**していました。

1998年7月発売の**プロアトラス98**は首都圏、東海、近畿、日本広域の各版が5,800円で販売され、ナビトラ連携以外にもNIFTY-Serveなどを経由する交通情報、天気、地震情報の表示を備えていました。[PC Watchの発売記事（1998年）](https://pc.watch.impress.co.jp/docs/article/980610/alpsmap.htm)。

1999年には**プロアトラス2000**が登場し、全国版DVD-ROMは1枚に複数地域の詳細地図を収録しました。DVD版の価格は12,800円でした。[ASCII.jpによる1999年の製品発表記事](https://ascii.jp/elem/000/000/305/305359/)。

地図上に表示する「点」が、自分や家族のGPS受信機から届いた本物の位置であるという体験は、当時かなり新鮮なものでした。国土地理院の地形図とは異なる一般向けの道路・施設情報を、パソコンの画面で扱う文化も同時に広がっていきました。

### ソニー IPS-3000／IPS-5000 ― GPSが電子工作用の部品だった時代

1990年代には、ソニーが**IPS-3000、IPS-5000**などのGPS受信ユニットを販売していました。現在のGNSSモジュールと同じように、位置を測定する部分が独立しており、外部のパソコンやマイコンに測位結果を渡せる製品です。表示器や地図、無線送信機までが一体になった完成品とは異なり、**受信した座標をどう活用するかは利用者が自由に考えられる**ことが大きな特徴でした。

1996年の医学・生体工学分野の論文では、IPS-3000とIPS-5000を用いて人間の行動を記録する実験が紹介されています。受信機がマイクロコンピュータを内蔵し、測位位置・高度・速度・進行方向・各衛星の情報を**約1秒ごとにシリアル出力**していたことが分かります。[『BME』第10巻第5号（1996年）、GPSによる行動観測の事例](https://www.jstage.jst.go.jp/article/jsmbe1987/10/5/10_5_39/_pdf/-char/ja)。

石川県林業試験場の研究報告に収録された**1997年1月のメーリングリストの記録**には、海流調査用のGPS付き漂流ブイについて、関係者が旧型の**IPS-3000を5台提供できる**と申し出たやり取りも残っています。すでに環境観測への利用や実験機材の融通が行われていました。[石川県林業試験場研究報告第28号（1997年1月の通信記録を収録）](https://www.pref.ishikawa.lg.jp/ringyo/publish/kenkyuuhoukoku/documents/28-4_nahotokainternet.pdf)。

また、IPS-5000はソニーのPCカード式ナビゲーションキット**PACY-CNV10**にも使用され、地図ソフト**Navin' You**と組み合わされていました。ソニーが2000年1月に公表した不具合情報には、この組み合わせで保存した走行軌跡の日時が誤る問題が具体的に記録されています。[ソニー：Navin' You Ver.4.0の走行パス問題](https://www.sony.jp/support/vaio/products/software/navinyou/info7.html)。

IoTという言葉が一般的になるよりずっと前に、**センサーの測定値をマイコンへ渡し、独自の装置や無線システムへ組み込む**という利用方法が、すでに市販のGPS機器で実現していたのです。

### ソニー独自の「IPSセンテンス」とNMEAの違い

当時のGPS受信機には、現在も利用される**NMEA 0183**のほか、ソニー独自の**IPSフォーマット**がありました。ソニーIPS系のデータは`SONY`で始まる固定長の文字列で、日時、緯度・経度、速度、方位、衛星の受信状態などを含みます。さらに、ソニーのカーナビ「コロンブス」系には`SMATC`で始まる別形式もありました。

| 比較 | NMEA 0183 | ソニーIPS | ソニーのカーナビ系 |
| --- | --- | --- | --- |
| データの識別例 | `$GPRMC`、`$GPGGA` | `SONY80...`、`SONY81...`など | `SMATC...` |
| 当時の代表的な速度 | 4800bps・8N1 | **9600bps・8N1** | 機種ごとに確認 |
| 形式 | 規格化された各種センテンス | ソニー独自の固定長データ | ソニー独自形式。公開情報が限られていた |
| 工作上の注意 | センテンスごとに項目を取り出す | 固定位置の値を切り出して解釈する<br>SONY製のIPSユニットやカーナビ内部で見られる | IPSと同一とみなさず、実際の出力を調べる |

この違いは、**ケンウッドTM-D700の取扱説明書**にも明記されています。ナビトラ用GPS入力の設定に「NMEA」「IPS」が存在し、それぞれ4800bpsと9600bpsの説明があります（[TM-D700取扱説明書、GPSレシーバー方式の設定](https://www.radiomanual.info/schemi/KENW_VU/TM-D700_S_user_JA.pdf)）。9600bpsでNMEAを出力する機器を「IPS」設定で扱える場合があることも記載されており、**通信速度の設定とデータ構造の解釈は区別**する必要があります。

アルインコの[パケット通信用ユニットEJ-50Uの取扱説明書](https://www.repeater-builder.com/alinco/pdf/ej-50u-im.pdf)には、IPS-3000／5000、PACY-CNV10への対応に加え、**110バイト固定の`SONY`形式と130バイト固定の`SMATC`形式**の説明があり、当時のデータ形式を調べる原資料として有用です。IPS-5000の`SONY81`形式については、2016年公開の[特許公報JP2016197093A](https://patents.google.com/patent/JP2016197093A/ja)にも文字列の構成が残されています。

GPSユニットの**IPSセンテンス**と、無線へ送る**ナビトラの`$PNTS`**は別の形式です。GPSの測位データを受け取った無線機や自作マイコンが、緯度・経度などを取り出してナビトラのパケットへ組み直します。

### PICのアセンブラでナビトラ発信機を作る

GPS受信機のデータをそのまま送るだけでも、自作ではシリアル信号の受信、必要な文字の抽出、位置の書式変換、AX.25フレーム生成、1200／2200HzのAFSK変調、PTT制御などが必要です。現在はC言語やArduino環境のライブラリを組み合わせられますが、当時の個人電子工作では**PIC16F84などのワンチップマイコンをアセンブリ言語で直接プログラムする**例がありました。

その具体例が、**『CQ ham radio』2000年2月号の「PICだけで作るGPS受信データ表示装置とナビトラ・ビーコン発生装置」**です。出版社の[当時の掲載ページ](https://www.cqpub.co.jp/cqham/CQHAMWWW/2000-2/hamcom.htm)には、アセンブラソース`GM38.ASM`とPIC書き込み用`GM38.HEX`へのリンクが残っています。製作者の[1999年11月の実験記録](https://www.ne.jp/asahi/ham/js1rsv/GPS/GM38.htm)では、**PIC16F84によるGPS表示機と、AX.25ビーコンを送る2号機**が紹介され、NRZI符号化、CRC、HDLCのゼロ挿入処理まで自前で実装する難しさが述べられています。

この製作例で使用したGPS受信機は**SONY IPSではなくGM-38**であり、NMEAデータを扱う例です。IPS形式の解析と、PICによるAX.25ビーコン生成は、**当時の電子工作で並行して行われた二つの技術**として区別できます。また、同じ製作者は2000～2003年にかけてPIC16F84／16F628による[レピーター制御装置とAX.25ビーコン送信機](https://www.ne.jp/asahi/ham/js1rsv/HAM/repeat.htm)も製作し、アセンブラのソースや回路を個人サイトで公開していました。

マイコン、GPS、FM無線機を組み合わせ、位置情報を送信するという仕組みは、現在のESP32やRaspberry Pi Picoによる[AX.25パケット通信の自作例](AX25パケット.md)と基本的には同じです。違うのは、当時は**測位モジュールそのものが貴重で、データ形式や変調処理も自分で解決する必要があった**ことです。

### ソニー「Navin' You」とGPS付きVAIO

ソニーの**Navin' You（ナビン・ユー）**は、パソコンに地図とGPSを結びつける別系統の製品でした。1998年のVer.2.0ではアルプス社の**プロアトラス98の地図データを利用可能**で、GPSアンテナ・PCカード付きMobile Packが59,800円、ソフト中心のHome Packが18,800円と発表されています。[ソニーによる1998年5月22日のニュースリリース](https://www.sony.com/ja/SonyInfo/News/Press/199805/98-045/)。

Navin' Youはそれ自体が**ナビトラの無線通信ソフトというわけではありません**。当時存在した「地図を扱うアプリ」と「GPSを受信する装置」の市場を示す例です。地図ソフトが異なれば、アマチュア無線の受信位置を重ねるためのインターフェースや変換プログラムも必要になります。

### ケンウッドのカーナビと、車載の組み合わせ

ケンウッドはアマチュア無線機と並行して、**CD-ROM／DVD-ROM地図を使うカーナビ**も開発・販売していました。GZ-700／GZ-770やDVZ-2000系列など、当時の機種はメーカーの[DVD・CDナビのサポート資料](https://www.kenwood.com/jp/faq/ce_navi/dvd/)に記録されています。

無線機が受け取ったGPSデータをカーナビ側の地図表示へ結びつける試みも行われました。ただし、**「ケンウッドのカーナビだからナビトラに対応する」という意味ではありません**。モデルごとに接続端子とナビトラ連携機能を確認する必要があります。現在のナビに当時のプロトコルを送っても、そのまま表示されるわけではありません。

### 既存のカーナビを改造してしまうアマチュア

1999年1月には、個人無線家がソニー製カーナビ**NVX-4**からGPS相当の信号を取り出し、ケンウッドの**MU-101**などを組み合わせてナビトラを試した記録が残っています。続いてトランシーバーと接続する変換回路を製作し、送信動作まで実験しています。

[JS1RSV「カーナビ（NVX-4）でナビトラをする」（1999年の実験記録）](https://www.ne.jp/asahi/ham/js1rsv/GPS/NVX4.htm)。

当時はGPS受信機の信号形式が機種によって異なり、車載機の内部信号を観察して変換する電子工作も行われていました。メーカーが用意していない組み合わせを動かすという、アマチュア無線らしい遊び方です。

## どのような情報を送っていたのか

ナビトラのデータは、**AX.25パケットの情報フィールドに`$PNTS`で始まる独自のテキスト形式**で格納されます。送信元の呼出符号に加え、GPSから得た緯度・経度、速度、進行方向、移動・固定などの状態を示すアイコン、短文を扱います。

CQ出版社の解説では、**16種類のアイコンと、アルファベット・数字・半角カタカナなどによる20文字のメッセージ**が紹介されています。日本語の短い文字を扱えたことは、位置情報中心に設計されたAPRSとの文化的な違いの一つでした。[CQ出版社の公開解説](https://www.cqpub.co.jp/hanbai/books/14/14951/14951_p145.pdf)。

この**20文字**という上限は後期製品だけの仕様ではありません。初代[TH-D7の取扱説明書（当時の保存版）](https://mackey.my.coocan.jp/images/th-d7_manual.pdf)と[ケンウッドTM-D700の公式取扱説明書](https://manuals.jvckenwood.com/download/files/B62-1227-00.pdf)でも、ナビトラメッセージは最大20文字と明記されています。わずかな文字数の中で、半角カタカナや数字・記号を工夫して近況を伝えることも楽しみ方でした。

### 気象観測――位置だけでなく、センサーの値まで送っていた

日本の無線家が送っていたのは、GPSで測った位置や20文字の近況報告だけではありません。**温度・湿度・気圧・水位などをセンサーで測定し、マイコンで数値化して無線で送り、遠方の受信局で表示する**実験も行われていました。現在なら「IoT」や「センサーネットワーク」と呼ばれる構成です。

| 時期 | 国内に残る実例 |
| --- | --- |
| **2002年5月** | 『HAM Journal』No.102が、**赤城山・地蔵岳の気象観測ロボット**を特集。JA1QPY・JP1COK両局によるセンサー、1チップCPU用のGID-ADC、アマチュア無線を使う遠隔計測・データ伝送を詳説 |
| **2003年8月** | 同誌No.107が、**PIC12F675による「ナビトラ向け温度ビーコン発生装置」**の製作記事を掲載。赤城山などでは、すでに山頂の温度をパケット通信やナビトラ・ビーコン形式で送る装置が運用されていた |
| **2004年12月** | JH4XSY局が、自宅で**1-Wireセンサーによる気温・湿度・気圧の観測**を開始。後年の記録には、Linuxでの収集、Xastirとの連携やCWOPへのデータ提供も登場する。これらはネットワーク経由の公開であり、各観測値を無線で送ったという意味ではない |

資料：[『HAM Journal』No.102「赤城山気象ロボットに見る センサー技術とデータ伝送」](https://www.cqpub.co.jp/HAMJournal/contents/102/HAMJ_102.htm)、[No.107「ナビトラ向け温度ビーコン発生装置」](https://www.cqpub.co.jp/HAMJournal/contents/107/HAMJ_107.htm)、[JH4XSY局「1-WIREで気象観測」](https://www.asahi-net.or.jp/~sx7h-iwmt/jh4xsy/wx.html)。

**2003年の温度ビーコンは、ナビトラが単なる移動局の位置表示ではなく、固定地点の測定値を知らせる用途にも使われた直接の証拠**です。ただし、ナビトラの `$PNTS` にAPRSの気象パケットと同じ標準フィールドがあったわけではありません。温度などを短文や独自の表示方式に載せる工夫と、専用の気象データ形式を持つ[APRS](APRS.md)のWX通信は、区別して理解する必要があります。

### 「IoT教育活用」が語られるより20年以上前の日本

2020年代には、アマチュア無線を「IoT人材育成」や教育・研究に活用することが改めて提唱されました。JARLは2020年12月にIoT人材育成を念頭に制度緩和を提案したと説明しており、2023年3月には教育・研究活動の位置づけの明確化を含む制度改正が行われています（[JARLの2023年会長挨拶](https://www.jarl.org/Japanese/4_jarl/4-1_Soshiki/jg1ktc_Kaichou_aisatu.html)、[同連盟による制度改正の解説](https://www.jarl.org/Japanese/2_Joho/2-2_Regulation/wireless_seido.html)）。

しかし、**センサーを読み取り、マイコンで処理し、無線で伝送し、遠隔地で表示するという技術活動そのものが、2020年代に新しく持ち込まれたわけではありません。** 少なくとも2002年には日本の無線家が赤城山で実際に取り組み、2003年にはPIC一個を使ってナビトラの温度ビーコンを自作する方法まで日本の技術誌に掲載されていました。さらに1990年代には、本記事で紹介したソニーのGPSモジュールやPICによる位置情報送信も行われています。

現在の制度改正には、参加しやすさを改善する新しい意義があります。一方で、日本のアマチュア無線が本来持っていた実験文化まで「これから始める新分野」として扱うのは、過去の実践者とその成果を見落とすことになります。**必要なのはIoTという新しい看板を掲げることだけではなく、国内の先人が実際に作り、試し、公開した回路・プログラム・運用ノウハウを継承し、さらに発展させること**でしょう。

- **AX.25**：フレームを送るための共通の「入れ物」。
- **ナビトラの`$PNTS`**：その入れ物に格納する位置・状態・文字の独自形式。
- **APRS**：同じ入れ物を使うが、位置・メッセージ・気象などの内容は別の形式で表す。

このため、**ナビトラ受信機でAPRSの位置が自動表示されるわけではなく、その逆も同様**です。ただし、パケットから取り出した情報を変換して新しいアプリケーションで表示することは、技術的には可能です。

## 活用例 ― 当時の遊び方と、今もできる実験

### 「20文字メッセージ・クラブ」――短い文章を無線で楽しむ

『[CQ ham radio』2000年5月号（2000年4月19日発売）の特集「ウォーキング・ハムライフのすすめ](https://www.cqpub.co.jp/cqham/CQHAMWWW/2000-5/index5.htm)」には、ナビトラ・フォーマットによる文字通信を楽しむ**「20文字メッセージ・クラブ」**が紹介されています。GPSで仲間の位置を調べるだけでなく、**最大20文字のメッセージをやり取りすること自体を遊びにしていた**のです。

当時の『CQ ham radio』の別号にも、**JS1JVR河原正美氏**による「ナビトラ運用と楽しみ～オニごっこ／20文字メッセージほか～」（252ページ）が掲載されており、位置情報を使った鬼ごっこや短文メッセージの交換が実際に紹介されていたことが分かります。同じ目次には、電子地図表示ソフト「Navitramap」を共同で作る企画も見られます。[CQ出版社：2000年の掲載目次](https://www.cqpub.co.jp/cqham/CQHAMWWW/2000-10/content.htm)。

「20文字メッセージ・クラブ」が継続的な会員組織であったのか、遊びの名称として使われたのかについては、この誌面紹介だけでは区別できません。しかし、**送れる情報が少ないことを制約として受け入れ、それ自体を交流の楽しみにしていた活動**があったことは、当時の専門誌から確かめられます。

### 仲間の車や移動局を探す

複数の移動局が定期的に位置ビーコンを発信し、固定局や別の移動局が受信して地図に表示します。電話で「今どこ？」と尋ねる代わりに、電波で更新された位置情報とメッセージを見て合流できます。ただし、**位置情報は常時更新されるわけではなく、通信圏外の間は古い位置のまま**です。

### 無線とインターネットをつなぐ

1998年のプロアトラス連携のように、固定受信局を作って受信パケットをサーバーへ渡し、各地の地図上へ表示する実験です。1990年代の実際の仕組みを、現在のOpenStreetMapやWebアプリで再現することも可能です。ただし、ネットへの公開には位置情報の公開範囲を十分に考慮します。

### ジャンクの復活・互換表示ソフトの自作

中古のTH-D7やTM-D700から受信したナビトラフレームを、シリアル端子やTNCモード経由でPCへ渡し、`$PNTS`を解析して地図へ描くことも考えられます。プロアトラスの古いCD-ROMやカーナビ本体がなくても、**位置情報の通信フォーマットと表示画面を新しく実装する**ことはできます。元の機器が発するパケットと新しいソフトが生成するパケットを比較すれば、互換性の実験にもなります。

## やり方 ― いまナビトラを再現するなら

### 機材構成

```text
GPS / GNSS受信機
    │ 位置・速度・方位（NMEA等）
ナビトラ対応機器／自作の $PNTS エンコーダ
    │ AX.25フレーム
TNC・1200bit/s AFSKモデム
    │ 音声入力・出力、PTT
144/430MHzなどのFMトランシーバー
    │ 電波
受信側TNC・デコーダ → $PNTS解析 → 地図表示
```

最も古典的な構成は、**ナビトラ対応ケンウッド無線機＋接続可能なGPS受信機**です。最初は受信側だけを作り、対応局や手元の旧機器が出力するデータを録音して解析すると理解しやすくなります。

1. **旧機種の仕様を確認**する。国内版TH-D7・TM-D700、TM-D710などは動作モードと対応するコネクタ、位置情報形式が異なります。
2. **GPS出力を確かめる**。外付け受信機のNMEA 0183またはソニーIPSなどの出力形式、シリアル通信速度、電圧・ケーブル配線を、機器の説明書と照らします。古いIPS系には9600bps、一般的なNMEAには4800bpsの設定例があります。
3. **対応FM周波数で受信**する。ケンウッド公式FAQには、ナビトラの過去の運用実績として**431.020MHz、431.070MHz／1200bit/s**が挙げられています。これは現時点で利用局がいるという保証ではありません。
4. **パケットを読み取る**。古いTNC、または[Dire Wolf](https://github.com/wb2osz/direwolf)でAX.25を復調し、データ部分の`$PNTS`形式を解析します。
5. **地図に反映する**。緯度・経度・アイコン・メッセージなどを自作ソフトへ渡し、OpenStreetMap等に重ねます。元の文字コードを処理するときは半角カタカナにも注意します。
6. **送信する場合**は、無線局免許・電波型式・使用区別・占有帯域幅などを確認し、短い試験パケットから始めます。相手局の存在と周波数の混雑も事前に確認します。

2024年更新の[ケンウッド公式FAQ](https://faq2.jvckenwood.com/kenwood/smart/faq/detail.aspx?a=102&id=83851&isCrawler=1)に周波数・速度の記録が残っていること自体が、旧システムの実験に有用な資料です。日常的な利用が現在も盛んという意味ではありません。

## なぜ姿を消していったのか

ナビトラの仕組みは当時としては先進的でしたが、日本国内で独自に発達したデータ形式と、対応製品・地図表示ソフトへの依存がありました。一方、世界規模で広がったAPRSには多数の無線機、地図ソフト、中継局、インターネットサービスが接続され、携帯電話やスマートフォンの地図利用も一般化します。

現在のナビトラは、新しく導入すれば仲間が当然いるというシステムではありません。しかし、**GPS・地図データ・無線機・パソコン・インターネットを、自分たちの手で結びつけた時代の実例**として見ると、現代のIoTや位置情報通信にそのままつながる発想が詰まっています。

ナビトラは、昔の無線機を思い出して懐かしむだけでなく、実機からデータを受信し、現代のソフトウェアで再生・解析してみる価値のある技術です。
