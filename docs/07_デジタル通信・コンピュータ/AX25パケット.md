# AX.25パケット通信 ― FM無線機でデータを送る

アマチュア無線の**パケット通信**は、音声の代わりにコンピュータのデータを短いまとまり（パケット）に分けて送受信する通信です。古いFMトランシーバーでも、音声入出力と送信制御を利用すれば実験できます。電話回線やインターネットがなくても、無線局同士で文章やデータを交換できるのが特徴です。

**AX.25**（Amateur X.25）は、そのためにアマチュア無線向けに整備されたデータリンク層の通信規約です。無線機や変調方式そのものの名称ではなく、**パケットに呼出符号や宛先、誤り検出情報などを入れる仕組み**を定めます。[APRS](APRS.md)や[ナビトラ](ナビトラ.md)もAX.25のパケットを利用しています。

| 項目 | 内容 |
| --- | --- |
| 主な用途 | 文字交信、電子掲示板（RBBS/BBS）、ファイル・メッセージ転送、DXクラスター、衛星データ通信、APRSなど |
| よく知られた無線方式 | VHF/UHFのFM音声回路を利用する1200bit/s AFSK（Bell 202系）、データ端子等を用いる9600bit/s級の通信 |
| 主な機器 | FM無線機、TNC（Terminal Node Controller）またはソフトウェアTNC、PCなど |
| 規格 | AX.25データリンク規約。物理層の変調方式、データ速度、アプリケーションの表示方法とは区別する |

## 概要 ― 無線をコンピュータの通信路にする

音声交信では、人間が相手の声を聞き、聞き取れなかった部分を聞き直します。パケット通信では、送信側が文字列などをフレームに組み立て、受信側がチェックサムに相当する**FCS（フレーム検査シーケンス）**で誤りを検出します。AX.25の接続型通信では、相手からの受信確認、再送、順序の管理も利用できます。

相手局がいない時間にも伝言を預けられる**RBBS（Radio Bulletin Board System）**、遠方まで複数局を介して情報を転送するノード、衛星に情報を蓄積するPACSATなどは、この仕組みの応用です。無線回線だけで動作することも、必要な部分だけインターネットへ接続することもできます。

### 何が送られるのか

典型的なAX.25のフレームには、次のような情報が入ります。

| 要素 | 主な役割 |
| --- | --- |
| フラグ | フレームの開始・終了を識別する |
| アドレス | 送信元・宛先の呼出符号とSSID、必要に応じて中継局 |
| 制御フィールド | 接続・確認・情報フレームなどの種類を表す |
| PID・情報 | 上位プロトコルの識別や文章・バイナリデータ |
| FCS | 受信したビット列の誤り検出に用いるCRC |

AX.25の呼出符号に付く `-1` や `-7` は**SSID**という副識別子であり、別の無線局免許を意味するものではありません。フレーム内の「宛先」は必ずしも実在する相手局とは限らず、APRSなどではプロトコル識別にも使われます。

**接続型**（コネクション型）では、相手とリンクを確立し、番号付きフレームを確認・再送しながら情報を渡します。一方、**UIフレーム**（Unnumbered Information）はリンク確立なしで送れるため、位置や短い情報を広く知らせるAPRSに向いています。UIフレーム自体には相手局からの再送保証はありません。

規格原文：[TAPR／ARRL『AX.25 Link Access Protocol for Amateur Packet Radio』Version 2.2](https://files.tapr.org/tech_docs/AX25/AX25.2.2.1997.pdf)。

## 成り立ちから現在まで

1970年代末にはカナダなどでアマチュアによる無線データ通信実験が行われ、1980年代にTAPR（Tucson Amateur Packet Radio）などがTNCの設計を普及させました。**1984年のAX.25 Version 2.0**はその後のパケット通信の共通基盤となり、1990年代には規格が改訂されました。

| 時期 | 出来事と変化 |
| --- | --- |
| 1978年 | カナダでアマチュアによる初期のパケット無線実験 |
| 1982～1985年 | TAPRのTNC試作、TNC-1、TNC-2キットの展開により既存のFM無線機をデータ通信に利用しやすくなる |
| 1980年代後半 | 日本でもTNCとパソコンによる接続交信、RBBS、地域間のノード・転送網が広がる |
| 1990年代 | 9600bit/s級のG3RUH方式、衛星の蓄積転送、DXクラスター、インターネットとの接続などへ展開 |
| 1990年代後半以降 | パソコンのサウンド機能を使うソフトウェアTNCが増え、位置情報通信APRSも普及 |
| 現在 | Dire Wolfなどのオープンソースソフト、マイコン、SDRを組み合わせて受信・復調・中継・独自アプリを構築できる |

日本の当事者の記録には、富士通FM-7、PC-9801、OASYSやTASCOのTNCを組み合わせて、転送ソフトの移植、文字コードの処理、ノード間の接続調整まで行った様子が残っています。当時のパケット通信は完成したサービスの利用というより、**参加者がネットワークそのものを作っていた活動**でした。[1980年代後半からの日本のパケット運用記録](https://www.ne.jp/asahi/ji1jci/kuromiya/ham/packet.html)。

## 活用例 ― 何をして遊べるか

- **端末同士の文字通信**：二局で接続型AX.25を使い、短文を交換する。伝送の遅延や再送の様子も観察できる。
- **RBBS・伝言板**：BBSを起動し、複数局が時間をずらしてメッセージを投稿・取得する。送信元と宛先、転送履歴をどう扱うかまで実験できる。
- **デジピーター・中継ネットワーク**：受信したパケットを中継する。経路や再送によって混雑が増えることも確認できる。
- **衛星・移動体通信**：アマチュア衛星や移動局とのデータ交換。通信可能な時間・経路が変化する状況を扱える。
- **独自プロトコル**：温度、電圧、位置、ゲームの状態、短いテレメトリーをAX.25の情報フィールドで送る。双方でデータ形式を決めれば独自の実験が可能になる。

とくに無線回線の誤りやタイミングを考慮した**小容量の分散型ゲームやメッセージ交換**は、1200bit/sでも十分に実験対象となります。接続型を使うかUIフレームでアプリケーション側が欠落に対処するかで、設計も変わります。

## やり方 ― FMトランシーバーとパソコンで始める

### 最初に必要なもの

1. **適切なアマチュア無線の資格・無線局免許**と、データ通信に使用できるFMトランシーバー。最初は受信実験から始めると、送信設備を触らず仕組みを確認できます。
2. **受信音声の取り出し**：無線機のスピーカー／データ端子と、PCの音声入力を接続します。PCのマイク入力へ過大な音量を加えないよう調整します。
3. **ソフトウェアTNC**：[Dire Wolf](https://github.com/wb2osz/direwolf)など。受信したAFSK信号を復調し、AX.25フレームを表示します。
4. **送信する場合の接続**：PCの音声出力を無線機のマイク／データ入力へ、PTT制御線を無線機の送信制御端子へ接続します。**PTT端子へPCやマイコンのGPIOを直接つながず、無線機に適したインターフェース回路を用います。**

```text
PC（ターミナル・アプリケーション）
         │ KISS / TCP・シリアル等
   TNC（Dire Wolf等）
         │ 音声入出力・PTT
      FM無線機
         │ 電波
      相手のFM無線機
         │ 音声・データ
      相手のTNC / PC
```

FM音声回路を使う**1200bit/s AFSK**では、一般に1200Hzと2200Hzの2種類の音を切り替え、FMトランシーバーの音声経路で送受信します。**9600bit/s級のG3RUH方式**は音声用のプリエンファシス／ディエンファシスなどを経由すると波形が崩れやすいため、対応するデータ端子や識別器出力を利用する必要があります。単にソフトの速度設定を9600へ変えるだけでは動作しません。

受信確認後、相手局を決めた短距離通信では、送信を始める前の待ち時間（TXDelay）、送信間隔、変調レベル、受信のDCD（キャリア検出）を調整します。パケットが受信できないときは、周波数や音量だけでなく、スケルチ、PCの音声加工機能、送信立ち上がり時間なども調べます。

!!! note "パソコンとの通信速度と電波上の通信速度は違う"

    TNCとPCのシリアル通信を9600bit/sや115200bit/sに設定しても、電波上が1200bit/sなら無線回線の速度は変わりません。音声回路とデータ端子の違いも、最初に切り分けると理解しやすくなります。

### TNCの二つの扱い方

従来のTNCは、端末で呼出符号や接続相手を設定して通信する**ターミナル／コマンドモード**を備えるものが多くあります。**KISS**（Keep It Simple, Stupid）モードではTNCにパケットの変復調・フレーミングを主に任せ、上位の処理をPC側のソフトで実装します。どのコマンドを用いるかは機種やファームウェアごとに異なります。

現在のDire Wolfでは、サウンドカードTNCを仮想KISSインターフェースとして利用できるほか、TNC相当の機能だけでAPRSの受信・中継・IGateにも利用できます。[公式ドキュメント](https://github.com/wb2osz/direwolf/tree/master/doc)。

### Hackadayの製作記録

[ESP32 AX.25/APRS TNC](https://hackaday.io/project/165940-esp32-ax25aprs-tnc) は、ESP32とハンディ機を接続し、スマートフォンなどとの連携を考えた製作記録です。受信データの処理やPTT回路に関する開発ログがあり、**プロジェクトは中断状態（shelved）**と表示されています。完成済みの一般向けキットとして紹介されているわけではありません。

[ESP32 TNC and Audio Relay for HF/VHF Packet Radio](https://hackaday.io/project/170710-esp32-tnc-and-audio-relay-for-hfvhf-packet-radio) は、**KISS TNCとして動くモードと、無線機の音声をPCへ中継するモードを切り替える**構成です。ESP32を用いた音声入出力・PTT・KISS通信のレイヤー分離を考える際の参考になります。

タスコ電機は日本のTNC市場で大きな存在でした。TAPRの1992年の会報には、同社の複数機種の実機評価と、TNC-2を基礎とした開発が記録されています。[TAPR『Packet Status Register』1992年7月号](https://files.tapr.org/psr/psr047.pdf)。中古品では**本体が動いてもRS-232Cケーブルの結線、専用マイク端子、EPROM内のファームウェア、電池液漏れ**などが問題になります。取扱説明書と合わせて調べるのも技術史の楽しみ方です。

## 送信するときの注意

日本の周波数使用区別、占有周波数帯幅、電波型式、免許条件を確認します。**AX.25の規格に対応しているだけで送信が許されるわけではありません**。430MHz帯には特有の30kHz上限があり、適用条件を[430MHz帯の記事](../02_無線の基礎/430MHz帯.md)で説明しています。データ通信の実験は、周囲の運用状況を受信で確認し、できるだけ短い送信から始めます。

また、一般的なアマチュア無線通信は**秘匿を目的とした通信に利用できません**。個人情報や認証情報をそのまま電波で流さないこと、共有地図などに公開される位置情報を理解してから送信することも大切です。インターネットへのゲートウェイを設ける場合、電波とネットワークの双方に異なる条件があることに注意します。
