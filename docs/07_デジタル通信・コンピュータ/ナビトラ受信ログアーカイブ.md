# ナビトラ受信ログアーカイブ ― 2005～2008年に交わされた短文

1990年代から2000年代にかけて、日本ではアマチュア無線を使って位置と短いメッセージを共有する「ナビトラ」が運用されていました。専用機器が使われなくなった後でも、**当時どのような情報が送られ、人々が何を楽しんでいたか**を知る手掛かりとして、受信情報サイトの記録が残っています。

旧`gps-packet.net`のナビトラ情報サイトには、各地で受信された局の位置、アイコン、メッセージなどを電子地図へ表示する仕組みがありました。[Internet Archiveに保存された2016年9月26日のトップページ](https://web.archive.org/web/20160926140356/http://www.gps-packet.net/)には、「30分以内」「一週間以内」の受信情報へのリンクが残っています。

最初に回収できた2007年と2008年の日付を持つ二つの記録から、**呼出符号・アイコン・メッセージだけでなく、受信日時、データ日時、移動速度、移動方向、グループコード**を抽出しました。緯度・経度を除外しつつ、無線家が当時どんな情報を送っていたのか検証できます。

- [**全257件の観測記録：速度・方位・時刻・グループコード付き（CSV）**](../assets/data/navitra-gps-packet-2007-2008-observations.csv)
- [**重複を統合した229種類の短文・アイコン索引（CSV）**](../assets/data/navitra-gps-packet-2007-2008.csv)

両CSVは同じ原資料から生成したもので、原本をCP932（Shift_JIS系）として読み取る[変換プログラム（Python）](https://github.com/CQAKIBA/AmateurRadio-Handbook/blob/main/tools/navitra_archive/parse_mps.py)も公開しています。

## 発見された2005～2008年の全保存記録

その後、Wayback Machineから回収された`.mps`のZIPに、2005年2月から2008年5月までの**計13ファイル**が含まれていることが確認されました。**SHA-256が同一の重複コピー4ファイルを除くと、9時点・計1,152件の観測記録**です。これまで紹介していた2007年・2008年の257件は、この全体の一部に相当します。

同じ呼出符号・地図アイコン・短文の組み合わせを統合すると、**728種類**の記録、SSIDを含むコールサイン表記では**460種類**が残ります。さらに、これらの表記から末尾のSSID（`-1`など）を除くと**254種類のコールサイン**になります。ただし、同一人物が複数の局を運用する場合やクラブ局もあり、254人の個人利用者を示す数字ではありません。

これらは**2005～2008年の異なる9時点を合算した記録**で、期間中の全運用局数や、一斉に存在した局数を表すものではありません。現代のAPRSと比較するには、対象期間・全国の受信網・ゲートウェイ数・SSIDの扱いなどをそろえる必要があります。一週間情報と30分情報の集計を単純比較して、利用者の増減を推定することもできません。

当時の市場環境を考える際は、**電子地図ソフト「プロアトラス」の販売継続と、アルプス社が運用していたナビトラ情報サイトの継承を区別**する必要があります。前者は2007年に『プロアトラスSV3』、2008年に『プロアトラスSV4』の新製品が発売されており、2007年の発売元発表ではシリーズ累計**80万本**の出荷実績を掲げています（[クレオの2007年5月の発表資料](https://www.creo.co.jp/pdf/press070522.pdf)、[2008年SV4の紹介](https://news.mynavi.jp/article/20080704-proatlas/)）。一方、[ナビトラ情報サイトの運営はアルプス社からFGPS関係者・有志へ引き継がれた](ナビトラ.md)と記録されています。**地図ソフト全体の販売台数をナビトラ利用者数とみなすことも、地図ソフトの発売終了年をナビトラ通信網の終了年とみなすこともできません。**

[**ナビトラ受信ログ検索 ― 2005～2008年の短文728種類をブラウザで閲覧**](ナビトラ受信ログ一覧.md)

元資料と機械的な分析には、[全1,152観測記録のCSV](../assets/data/navitra-gps-packet-2005-2008-observations.csv)、[重複を統合した短文728種類のCSV](../assets/data/navitra-gps-packet-2005-2008.csv)、[9時点の原ファイルSHA-256と重複関係をまとめたJSON](../assets/data/navitra-snapshot-manifest.json)を利用できます。**元の座標や局別追跡URLは再掲載せず、受信日時・速度・方位・アイコン・グループ・メッセージは保存**しています。全1,152件中11件のメッセージでメールアドレスのみを理由付きで省略しました。

CSVは保存・再解析のための正本です。ブラウザ閲覧用の表はこのCSVを元にあらかじめ静的HTMLとして生成しているため、JavaScriptが無効でも原文を読むことができ、検索エンジンの収録もJSによる実行に依存しません。JavaScriptは検索・分類・ページ切替にのみ使用します。ZIPから資料を再生成するための[Pythonスクリプト](https://github.com/CQAKIBA/AmateurRadio-Handbook/tree/main/tools/navitra_archive)も公開しています。

### GPSの進行方向によって変化する地図アイコン

2005～2008年の`.mps`には、**移動局A～Eの五つのアイコングループ**と、それぞれに**北・北北東・北東……という16方位の記号**が用意されていました。ケンウッド[TM-D700の取扱説明書（「自局アイコンの登録」）](https://manuals.jvckenwood.com/download/files/B62-1227-00.pdf)でも、ナビトラの自局アイコンとして15種類から選べることが説明されています。ナビトラの[ `$PNTS`フォーマットに関する記録](https://wikiwiki.jp/dcn/Navitra/PNTS)には、進行方向を**64段階**で表現するフィールドもあります。

同一局`JR6BJN-7`の移動方向と地図アイコンを時期ごとに比較すると、次のように変わっています。

| 保存時期 | 地図アイコン | 方向（保存値） | 速度（保存値） |
| --- | --- | ---: | ---: |
| 2005年2月 | 南南西 | 213.8 | 50.0 |
| 2006年4月 | 東南東 | 129.4 | 0.0 |
| 2006年10月 | 東 | 118.1 | 19.0 |
| 2007年7月 | 南東 | 151.9 | 0.0 |
| 2008年5月 | 南 | 208.1 | 9.0 |

全1,152観測のうち**361件が移動局A～Eのアイコン**で、方向の数値が記録されている357件では、方位名の変化と数値の変化が対応します。**同じSSID付きコールサインでも複数の方向アイコンが登場する例**が多数あり、閲覧側が移動局の進行方向に応じて16方位の絵柄を選択していたことを強く示しています。

ただし、保存された方向とアイコン名の区切りは、一般的な16方位の中心角を基準とする区分と一致しません。**具体的な角度→記号の換算規則や、変換処理を担ったソフトウェアの実装までは未確認**です。また速度が`0.0`でも方向が残るレコードがあるため、アイコンの方向が実際に走行中であることまで示すとは限りません。これはナビトラ独自の地図表示文化を考える手掛かりですが、APRSにも位置・速度・進行方向を扱う仕組みがあり、**「APRSでは不可能」といった断定はできません**。

### 漢字メッセージと自作コンピューターの痕跡

当時の地図上の表示には、通常の英数字・半角カタカナによる短文のほかに、**漢字を含む日本語**やマイコン自作機器の名前も残されています。

| コールサイン | 地図上の分類 | 保存されたメッセージ | 最古の確認時期 |
| --- | --- | --- | --- |
| JP1LZD-1 | 民家 | `茨城県稲敷郡固定` | 2006年10月 |
| 7L4TZU | 民家 | `AKI-H8ナビトラサーバ2003!` | 2005年2月 |
| JH1ZNX-1 | 店舗 | `セキジュウジトウキョウトシブ` | 2005年2月 |
| JI1ZJJ-1 | 店舗 | `セキジュウジタチカワキュウゴ` | 2005年2月 |
| 7L1QKS | レピーター | `北西15階ビル建築中` | 2006年4月 |

`AKI-H8`という文字列は、当時電子工作で使われた**秋月電子通商のH8マイコンボード・キットの製品名**と一致します（[秋月電子通商のH8関連製品](https://akizukidenshi.com/catalog/r/rh8/)）。このメッセージは、自作のナビトラサーバーを名乗る装置が実際の地図記録に存在した証拠です。ただし、**どの型番のH8を使ったか、名称末尾の「2003」が開発年を意味するか**は分かりません。

赤十字関連の名前を掲げる局の記録も、災害救護や地域の活動とアマチュア無線が接する場面を考える手掛かりです。一方、**メッセージ中の自称だけで、赤十字の公式施設・業務として運用されていたことが証明されるわけではありません**。「北西15階ビル建築中」の記録は、設備周辺の建築物や受信環境の変化を知らせる情報だった可能性がありますが、具体的な建物や実際の影響は不明です。

また、ナビトラの標準的な20文字メッセージは[1バイト文字として記録](https://wikiwiki.jp/dcn/Navitra/PNTS)されており、ケンウッド機の文字入力も英数字・カタカナ・記号を基本とします（[TM-D700の説明書](https://www.radiomanual.info/schemi/KENW_VU/TM-D700_S_user_JA.pdf)）。そのため、**`.mps`に漢字があることから、漢字が通常のナビトラ無線フレームで送られたと結論することはできません**。PCによる独自処理や、サーバー側での表示文字列の付加・加工、標準外の拡張などが考えられます。実際のAX.25フレームが残っていないため、発信時にどの文字コード・形式を使っていたのかは確定していません。

## データ形式と保存上の取り扱い

元の記録は、`mapserver script ver = "1.0";`で始まる電子地図向けのテキストデータです。各`point`に緯度・経度、呼出符号、アイコンのグループ番号、受信日時・データ日時・移動速度・方向・メッセージなどが設定されています。**これはAX.25フレームやナビトラの`$PNTS`センテンスを、そのまま記録した生ログではありません。** 地図表示のために変換された情報です。

### アルプス社「マップサーバ技術」――.mpsを読める理由

この`.mps`は、アルプス社（現存する各種OSSとは別の製品技術）が**「マップサーバスクリプト」**として公開していた書式です。単にWebサーバーが配る地図画像ではなく、**位置・文字・表示記号を小さなスクリプトとして交換し、ユーザーのパソコンにインストールされた電子地図で描画する**仕組みでした。

アルプス社の[「マップサーバ技術」Webサイト（Internet Archive、2008年5月24日保存）](https://web.archive.org/web/20080524205732/http://www.alpsmap.co.jp/mapserv/)には、「マップサーバスクリプト仕様書」、「マップサーバスクリプト記号表」、FAQなどの資料が残されていました。**2001年6月29日付の[「マップサーバスクリプト仕様書 Ver.1.32（暫定版）」](https://web.archive.org/web/20061126121438/http://www.alpsmap.co.jp/mapserv/mapsrvr.html)の本文**も、2006年11月26日のWebアーカイブから確認できます。FAQではプロアトラス97・98の対応関係や、スクリプトVer.1.22とVer.1.52の互換性にも言及しています。**仕様書の版と個々のスクリプトが宣言するバージョンは同一ではありません。**

2001年の仕様書には、次の事項が明記されています。

| 項目 | アルプス社の規定 |
| --- | --- |
| 目的 | 地図データベースとアプリケーション間で、位置情報・表示命令などをテキストで交換 |
| ファイル形式 | 拡張子`.mps`、MIMEタイプ`application/x-mapserver`（3.3・3.4節） |
| 文字コード | `kanji code="jis"`、`"sjis"`、`"euc"`。指定がない場合はShift_JIS（4.2.2.1節） |
| 座標 | **緯度、経度**の順。度の小数表記、度分、度分秒に対応（4.1.4.1節） |
| 測地系 | `georef system="WGS84";`で明示可能。省略時はその地域で通常使われる測地系を想定（4.2.2.2節） |
| 表示グループ | `gid`はピリオド区切りの**最大7階層**。各階層の数値は0～255で、階層そのものの意味は規定しない（4.1.4.2節） |
| 終了命令 | **`mapserver end;`**が正式な書式（4.2.1.1節） |
| 自動更新 | `addon updatable="yes"`は、次回更新日時が未定の場合に閲覧側が適当な間隔で更新を確認する指定（4.2.5.1節） |

とりわけ**測地系は重要**です。`georef`が省略された古いファイルの座標を、検証せずに現代のWGS84地図へ直接重ねると、位置がずれる場合があります。日本測地系と世界測地系の差も考慮する必要があります。また、`addon updatable="yes"`は**閲覧ソフトの更新確認機能**を表し、送信局や無線受信ゲートウェイが稼働中であることを証明しません。

同じ仕様書には、`point`以外にも`line`・`circle`・`rect`・`area`、マップサーバ側で位置を入力する`input`、`pick`など、多数の命令が定義されています。マップサーバスクリプトは単なるナビトラ専用の保存形式ではなく、**電子地図の機能を外部アプリケーションへ公開する汎用インターフェース**でした。

さらに、**1999年3月の『UNIX MAGAZINE』「インターフェイスの街角（16）」**には、`mapserver script ver="1.0";`、`group`、`point`、`disp`、`mapserver script end;`を使う実例が掲載され、ProAtlasとソニーNavin' Youの位置表示スクリプトを比較しています（[当時の掲載記事PDF](https://www.pitecan.com/UnixMagazine/PDF/if9903.pdf)）。ナビトラの2007・2008年の保存データは、この1990年代から存在した仕組みの延長に位置しています。

```text
GPS・ナビトラ送信局
    ↓ AX.25による位置・メッセージの送信
受信局・情報集約サーバー
    ↓ マップサーバスクリプト（.mps）をHTTPで配布
利用者のブラウザ・対応地図ソフト
    ↓ ローカルの地図データに位置・文字・アイコンを重ねる
電子地図上のナビトラ局表示
```

`0.mps`と`1.mps`に実際にある命令をまとめると、次のようになります。両ファイルの末尾には`disp area="current" scale="5000000";`と、仕様書でも正式な終了命令である`mapserver end;`が記録されています。ただし、**2001年の仕様書で紹介される`disp`の書式は`oid`・`first`・`last`・`all`・`pos`であり、`area="current"`はこの文書で確認できません**。後の版やソフト独自の拡張である可能性があり、確定には追加の版の資料が必要です。一方、1999年の雑誌掲載例には`mapserver script end;`という形が示されており、**複数時期の実例の差を残しておく**必要があります。

| 命令・属性 | 記録における役割 |
| --- | --- |
| `mapserver script ver = "1.0";` | スクリプトのバージョン宣言。アルプス社のWebサイトが後年紹介した**Ver.1.32の仕様書とは別の値** |
| `theme str=` | 「ナビトラ一週間情報」などの表示用表題と更新日時 |
| `addon url= ... updatable="yes"` | 更新可能な情報チャンネルの配布元URL |
| `group gid= ... gname=` | 階層的なアイコングループ名。移動局A～E、レピーター、民家など |
| `pointstyle=`、`iconsize=` | 地図上で使う記号番号とアイコンの大きさ |
| `point oid= ... gid= ... pos= ... str= ... info= ... url=` | 個々の局の位置・呼出符号・情報欄・リンクなどを収める地図上の点 |
| `message str=`、`disp area= ... scale=`、`mapserver end;` | 受信件数などの表示メッセージ、地図の表示範囲、スクリプト末尾 |

`gid="2.8"`のような値は、**ピリオドで階層化された地図表示識別子**です。各桁の意味は仕様上固定されていませんが、今回の保存ファイルではグループ2が「移動局C」、その下の番号8が「南」に対応します。これは`info`内の「グループ: 001」「グループ: SKY」などの文字列と**別の項目**で、いずれもAX.25の中継VIA経路を直接示すものではありません。

公式の「マップサーバスクリプト記号表」は、番号と図形の対応を確認するために必要な資料ですが、Web保存版の画像本体は確認できていません。アイコンの**名称と階層は`.mps`の`group`定義から読めますが、記号の元の絵柄すべてを再現できるわけではありません**。

なお、正式な仕様は複数の版が公開されていたため、現在の[変換プログラム](https://github.com/CQAKIBA/AmateurRadio-Handbook/tree/main/tools/navitra_archive)が実装しているのは、**今回確認できたナビトラ用`.mps`の`group`・`point`書式を読み取る範囲**です。すべてのマップサーバスクリプト、線や面などを完全解釈できる汎用ソフトではありません。

### 数値・時刻・グループ情報を含む観測記録

257件の[観測記録CSV](../assets/data/navitra-gps-packet-2007-2008-observations.csv)では、元の`point`ごとに以下の情報を保存しています。

| 列 | 内容 |
| --- | --- |
| `snapshot`、`source_file`、`source_oid` | 2007年・2008年のどちらのファイルの、何番目の地図レコードか |
| `callsign` | 当時の表示呼出符号。AX.25のSSIDを含む |
| `icon_gid`、`icon_group`、`icon` | 原資料のアイコン識別番号、移動局A～Eなどのグループ、16方位やレピーターなどの名称 |
| `received_at_raw`、`data_at_raw` | 受信日時と送信データに記録された日時。日付のない記録は原文の`なし`を保持 |
| `speed_raw`、`direction_raw` | 元資料の「移動速度」「移動方向」にある数値をそのまま保存 |
| `reported_group_code` | 元資料の「グループ」欄にある識別子 |
| `message`、`redactions` | メッセージ本文と、連絡先を伏せた場合の種別 |

**257件のうち、移動速度が0以外のものは51件、移動方向が0以外のものは83件、データ日時が`なし`なのは68件**でした。0という数値が静止状態を意味するのか、情報の欠測を含むのかは、このデータだけでは区別できません。また、速度の単位や日時の時刻系が原本に明示されていないため、値の換算や時差補正はしていません。方位も、原本が表示した値をそのまま残しています。

「グループ」欄には`000`（221件）、`001`（28件）、`SKY`（2件）、`KNG`（2件）、`109`（2件）、`151`（1件）、`GPR`（1件）が残っています。**これらの意味や、特定の中継ネットワークとの関係は未確定**ですが、後年の資料との照合に役立ちます。

一方、この`.mps`に**AX.25のVIA経路そのものは記録されていません**。`WIDE`、`UIDIGI`、`KING Gate`などの語はメッセージや設備名として実際に出現しますが、これらを経由したパケットの完全な中継履歴が保存されているわけではありません。また、独立した気温・湿度・気圧の測定欄も見当たりません。気象ビーコンそのものの歴史については[ナビトラの記事](ナビトラ.md)で紹介しています。

### 短文索引と、個人の連絡先の取り扱い

229種類の[短文索引CSV](../assets/data/navitra-gps-packet-2007-2008.csv)は、従来どおり`snapshot`・`callsign`・`category`・`icon`・`message`の5列で構成されます。`snapshot`には、両保存日に同じコールサイン・アイコン・短文が見つかった場合、二つの日付を`;`で連結しています。

アマチュア無線上で公開送信された情報にも、後年の再掲では慎重に扱うべき個人の連絡先があり得ます。そこで、**正確な緯度・経度と元サイトの個別局追跡URLは再掲せず、観測時刻・速度・方位・短文などの技術的な記録は残す**方式としました。

メッセージ中にあった電子メールアドレスは、**`[メールアドレスのため掲載省略]`**に置換しています。これは**観測記録で3件、重複統合後の短文索引で2件**です。個人の連絡先だったこと自体は、当時の無線とインターネット文化の交差を示す情報として残ります。対して、`TM-D700@mobile`や`ゴンゲンヤマビーコン@5W`など、メールアドレスではない`@`を含む表現は元のまま保存しました。電話番号や詳細な住居番地についても、発見された場合は理由を記した置換表記とします。

この置換表記は**原文の20文字の一部ではありません**。現在の閲覧用に付した表示です。その他の短文は文字コードをUTF-8へ変換し、末尾の空白などを整えたものを基本としています。空のメッセージ8件も、記録の存在自体を残すため削除していません。

元データの同一性を確認するためのSHA-256値は、以下のとおりです。

| 原資料 | SHA-256 |
| --- | --- |
| 一週間情報：`0.mps`（2007年） | `affc5c20b39243157e507493da244056d864e805d62524b4ad7c572f5bd9e781` |
| リアルタイム情報：`1.mps`（2008年） | `ac65ea66e9ed8181a17a918172a856f7406a89013bcffa6d766af28598028886` |

## 残されたものと、分からなくなったもの

**2016年にWebページがアーカイブされた事実は、2016年まで無線の受信・地図情報の更新が稼働していた証拠ではありません。** 今回の二つのデータは2007年と2008年の時点を記録しており、その後いつゲートウェイやサーバーの更新が終了したかは、この資料だけでは確定できません。

かつて日本で盛んだったパケット通信の電子掲示板（RBBS）も、利用者が実際に書いた文章や日々の運用記録が残りにくく、当時どんな交流や実験が行われていたかを後から調べることが困難になっています。ナビトラの短文はわずか20文字程度ですが、**その一つ一つが、当時の無線家の活動を具体的に伝える史料**です。

アルプス社の当時の「マップサーバスクリプト仕様書」各版や記号表は、書式を忠実に再現するうえで重要です。Wayback Machineで閲覧できる版の原HTML、PDF、保存ファイルの所在をご存じの方も、史料の照合に役立てられます。

別の年の`.mps`、ナビトラサーバーの動作記録、NavitraMapの画面や当時の運用資料をご存じの方は、[本ハンドブックのGitHub Issues](https://github.com/CQAKIBA/AmateurRadio-Handbook/issues)から記録を共有できます。
