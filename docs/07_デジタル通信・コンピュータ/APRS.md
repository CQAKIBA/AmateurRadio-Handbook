# APRS ― AX.25パケットで位置と情報を共有する

**APRS（Automatic Packet Reporting System）**は、アマチュア無線を使い、局の位置だけでなく、短いメッセージ、気象、測定値、活動地点などを周囲の局と共有するために生まれた通信システムです。衛星測位のGPS／GNSSと結びついた「自分が今どこにいるか」の表示で知られていますが、**GPSを持たない固定局も利用でき、移動体の追跡だけが目的ではありません**。

APRSの一般的な無線経路には[AX.25パケット通信](AX25パケット.md)が利用されます。受信した位置情報などは対応ソフトで地図に表示でき、インターネットへ中継されたものは遠方からも閲覧できます。無線だけで情報を交換する構成も成立します。

| 項目 | 内容 |
| --- | --- |
| 開発者 | Bob Bruninga（WB4APR、米国） |
| 主な情報 | 位置・移動方向・速度、短文メッセージ、気象、テレメトリー、オブジェクト |
| 代表的な無線方式 | 144MHz帯等の1200bit/s AFSKパケット、地域によって9600bit/s等 |
| 伝送経路 | 局から直接受信、デジピーターによる再送、IGate経由のAPRS-IS |
| APRSの特徴 | 受信局が都度接続しなくても受信できるブロードキャスト型の情報共有 |

## 概要 ― 地図に表示するだけではない

APRSは「位置を送れば便利」というだけでなく、周囲の局がどこで何をしているかを小さなパケットで共有する発想から生まれました。たとえばイベント会場に設けられた連絡局、移動局、気象観測局、衛星の観測対象などを地図上に配置し、メッセージを交換できます。

位置情報を含むデータを定期的に送る運用を**ビーコン**と呼びます。多くのAPRSパケットはAX.25の**UI（Unnumbered Information）フレーム**で送られ、通常の接続型パケット通信のような回線確立は行いません。届かなかったビーコンはそのまま失われますが、次のビーコンが届けば新しい位置が分かるため、短い情報の定期的な共有と相性がよい方式です。

| 用語 | 意味 |
| --- | --- |
| **Tracker** | GNSSなどから位置を取得して、無線でAPRSパケットを送る端末 |
| **Digipeater** | パケットを受信し、定められた条件で無線へ再送するデジタル中継局 |
| **IGate** | 無線で受信したAPRS情報をAPRS-ISへ送る、または規則に沿って逆方向の中継も行うゲートウェイ |
| **APRS-IS** | インターネット上でAPRSデータを集約・配信するネットワーク。無線経路そのものではない |
| **Object / Item** | 無線局以外の地点や対象物を地図に表示するための情報 |
| **Telemetry** | 電圧、温度、センサー値などを送る仕組み |

APRS-ISの受信データを地図に表示する[aprs.fi](https://aprs.fi/)のようなサービスもあります。ただし、**地図サイトに表示されないことは電波が届かなかった証拠ではなく、表示されたからといって指定された相手局まで無線で届いた保証でもありません**。IGateの有無、通信経路、フィルター、ネットワーク障害などで見え方が変わります。

## 成り立ちから現在まで

APRSの開発者Bob Bruningaは、1984年に移動体の位置や状態をパケット通信で共有する原型を実験し、1992年にAPRSとして技術を発表しました。その後、地図表示ソフトが複数のOSに広がり、インターネットと中継する仕組みや、TNC・GPSを内蔵した無線機が普及します。

| 年・時期 | 主な変化 |
| --- | --- |
| **1984年** | Bob Bruningaによる位置・状態報告の初期システム |
| **1992年** | APRSがTAPR/ARRLのデジタル通信会議で発表される |
| **1994～1995年** | MacAPRS、WinAPRSなどの地図表示・運用ソフトが登場 |
| **1996～1997年** | javAPRSやAPRServe等が、Webと世界規模のAPRS情報交換を結びつける |
| **1998年** | 海外向けケンウッドTH-D7A/Eなど、APRSを無線機側に組み込んだ製品が登場 |
| **2007年** | 日本国内向けTM-D710シリーズにAPRSを標準搭載。従来のナビトラと併用できる製品が登場 |
| **2020年代** | 市販機のほか、Dire WolfやESP32による自作Tracker・IGate・Digipeaterが利用される |

日本の1990年代の位置情報通信には、別に開発された[ナビトラ](ナビトラ.md)がありました。国内向け初期TH-D7・TM-D700にはナビトラ、海外向けにはAPRSが採用されていたため、**名前が似た機種でも最初から同じデータ形式が使えるわけではありませんでした**。後年の両方式対応機でこの違いは縮まりました。

開発者本人の回想：[Bob BruningaによるAPRSの歴史](https://www.gx4mws.uk/tech-tips/aprs/aprs-history/)。規格本文：[『APRS Protocol Reference』Version 1.0](https://www.aprs.org/doc/APRS101.PDF)。

## 活用例 ― 位置情報から独自の情報共有へ

### 自分や友人の移動を地図に表示する

車や自転車、徒歩の移動局がGNSSで取得した位置を送信します。離れた場所の局が直接受信できるだけでなく、IGateを経由すればネットワーク上の対応ソフトからも表示できます。移動局が通信圏外なら、その間の位置は通常受け取れません。「常に追跡できる」とは限らないことを理解して利用します。

### イベント・山岳移動・衛星運用

会場の集合場所や臨時設備などは**Object**として共有できます。観測局や測定局の位置、気象情報も重ねられます。衛星を介してパケットを交換する実験も存在しますが、衛星の運用モードや周波数は時期によって変わるため、その時点の衛星運用情報を確認します。

### センサーネットワーク・ゲーム

APRSは**位置、短い文字列、テレメトリー**などを扱うため、温度・電圧・気象観測、スタンプラリー、局同士の位置を使ったゲームなどにも応用できます。独自のデータを一般のAPRSネットワークへ送る場合は、規格に合った形式と運用マナーが必要です。ローカルな実験だけで閉じたAX.25フレームを使う方法もあります。

## やり方 ― 受信から送信まで

### 1. まず聞いてみる

日本のAPRSで使われてきた代表的な周波数は次のとおりです。これらは**全国一律の専用周波数を保証するものではなく、運用例**です。

| 周波数 | よく見られる方式 |
| --- | --- |
| **144.660MHz** | 1200bit/s AFSK |
| **144.640MHz** | 9600bit/s級のパケット |

出典：[ケンウッド公式FAQ（2024年更新）](https://faq2.jvckenwood.com/kenwood/smart/faq/detail.aspx?a=102&id=83851&isCrawler=1)。他国では北米144.390MHz、欧州の多くでは144.800MHzが一般的であり、**外国向け無線機に設定済みの周波数をそのまま日本で使用しない**ようにします。送信には国内の免許条件・使用区別の確認が必要です。

受信に必要なのは、対応するFM受信機、PCの音声入力、[Dire Wolf](https://github.com/wb2osz/direwolf)などのデコーダーです。1200bit/s AFSKはFM音声として聞くと短い「ピギャッ」という音になります。無線機のスピーカー出力の音をPCへ入力し、適切な入力レベルでデコードできるか試せます。受信するだけならPTT配線は不要です。

### 2. パケットを読む

以下は**説明用に作った架空のパケット例**です。実際の無線で受信した交信記録ではありません。

```text
JA1ABC-9>APRS,WIDE1-1:!3540.12N/13942.34E>Mobile test
```

先頭には送信局 `JA1ABC-9`、宛先識別 `APRS`、中継経路 `WIDE1-1` を記し、コロン以降に位置などの情報を置く**TNC-2形式の表示**です。実際のAX.25の電波上のビット列は、画面に出るこの文字列そのものとは異なります。位置の値は度・分表記であり、小数度と取り違えないようにします。

`WIDE1-1`などの経路指定は中継の動作を左右します。適当に多数の中継段数を指定すると、必要以上に同じパケットが再送されて混雑の原因になります。周辺ネットワークの案内に合わせて最小限にします。インターネットでしか使わない運用は、無線側の混雑とは別に考えます。

### 3. 自局のビーコンを送信する

GNSSを備えた対応無線機なら、呼出符号、SSID、シンボル、送信間隔、周波数、速度、送信経路などを設定して運用できます。PC＋FMトランシーバーの構成なら、ソフトウェアTNCに送信音声・PTT制御・GNSS位置情報を渡します。

- 初めは**固定した位置と低頻度の短いビーコン**から試し、受信局の記録と突き合わせます。
- GPS機器と無線機の接続には、**NMEA 0183などの位置データの形式**、ボーレート、端子電圧を合わせます。
- 移動局では速度・進路の変化に応じ送信間隔を変える**SmartBeaconing**という考え方もありますが、設定を誤ると過剰な送信になります。
- メッセージ機能は対応局間で利用できますが、無線経路やゲートウェイによって到達・応答が保証されるわけではありません。

### 4. IGateやDigipeaterを試す

固定局の受信音をDire Wolfへ渡し、受信したパケットをAPRS-ISへ中継する**受信専用IGate**から始める方法があります。無線側へ再送信する双方向IGateやDigipeaterは、**パケットの重複防止、経路制限、送信回数、インターネットからの送信条件**を慎重に設定する必要があります。これらの動作は単に「受信したものを何でも再送信する」ことではありません。

!!! warning "LoRa-APRSと従来の1200bit/s APRSは別の無線方式"

    LoRaの無線変調を使ってAPRSと連携するプロジェクトもありますが、**従来のFM音声AFSKのAPRS受信機では、そのLoRa信号を直接復調できません**。さらに日本の430MHz帯には30kHzの占有帯域幅制限があり、海外でよくあるBW125kHz・250kHzのLoRa設定をそのまま送信することはできません。[430MHz帯の記事](../02_無線の基礎/430MHz帯.md)を参照してください。

## 位置情報の公開と無線局としての注意

APRS-ISや地図サービスへ送られた位置情報は、多数の第三者が閲覧でき、履歴として残る場合があります。自宅や移動経路を常時公開したくない場合、送信の有無・内容・精度・頻度をあらかじめ考えます。インターネット上の表示設定だけでは、**無線で直接受信する第三者への秘匿にはなりません**。

無線側のビーコンやメッセージはアマチュア業務として取り扱い、国内の免許条件・使用区別・混信防止に従います。**APRSは業務用の位置監視サービスや、確実な救助要請手段の代わりではありません**。送信の成否と必要な相手への到達を分けて扱います。
